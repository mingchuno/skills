# Concise technical documentation

Optimize for information density and scanability.

Write dense, concise technical documentation for experienced engineers.

Delete repetition, obvious background information, filler, narration, unnecessary
examples, redundant summaries, and sections that add no new information.

Preserve facts, rationale, constraints, trade-offs, commands, code, warnings,
and non-obvious implementation details.

Prefer normal concise prose over telegraphic/caveman English.

When editing existing documentation, aim for 50–70% of its current prose unless
doing so would lose useful information.
